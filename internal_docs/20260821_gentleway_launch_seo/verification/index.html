What was built

www.gentleway.ink serves the Gokyo no Waza poster with the full Monument Labs product SEO package (matching Camera Shy / cosmo / Clean Markdown): a real mark (the belt knot) with the canon favicon set and a 1200×630 OG card; site.webmanifest, robots.txt, llms.txt; canonical + OG/Twitter meta + JSON-LD on every route; a sitemap with image entries; 40 per-throw pages at /throws/[id] so the 25k words of mechanic / analogy / why-it-maps prose are in server HTML instead of hidden in a modal; a styled 404; vercel.json redirects (.vercel.app host and trailing slashes); a brand row and a "Built by Monument Labs" footer; and a Gentle Way tile, Product node and footer link on monumentlabs.io. The 40 analogies, images, palette, fonts and the hover / flip / modal interaction are unchanged.

End-to-end run-through

The golden path a visitor (or a crawler) takes, in order. Each step is proven by the screenshot named.

  1. Shared link renders the OG card (sprint1_og_card): mark, wordmark, tagline, gentleway.ink, Monument Labs credit.
  2. Land on / (sprint2_index_desktop): brand row, etymology line, the poster title and grid; head carries canonical, OG, four icon links, JSON-LD with the 40-item ItemList.
  3. Click a card (sprint2_index_modal): the modal opens, URL stays /; the card is an <a> so cmd-click and crawlers get the page.
  4. Modal "Open page →" navigates to /throws/tai-otoshi.
  5. Throw page, desktop and mobile (sprint2_throw_desktop, sprint2_throw_mobile): pair + Mechanic / Analogy / Why it maps in server HTML, per-throw OG JPEG and WebPage JSON-LD in the head, prev/next wrap around the Gokyo.
  6. Bad URL (sprint2_error_404): styled 404 on paper, noindex, link back to the poster.
  7. Back on monumentlabs.io (sprint3_ml_tiles_light, sprint3_ml_footer): the product tile and footer link point at gentleway.ink; the Organization @id the poster's JSON-LD references now exists.

Not exercised in the browser: cmd-click on a card (modifier clicks are let through to the browser in ThrowCard.onClick; same code path as any <a href>) and mobile tap-to-flip (desktop Chromium reports hover: hover even at 390 px; the logic is unchanged from before this work).

Gotchas / deviations

Routine calls made during execution, collected from each sprint's Deviations block in the plan.

  • OG tagline (S1): the long tagline auto-wrapped to two lines with an orphan "them.", so the card uses the short one, "Forty judo throws, explained with everyday physics." The long tagline is unchanged everywhere else (llms.txt, the poster, the ML tile).
  • favicon.ico (S1): overwrote the starter icon (16/32/48). Mark sits slightly below optical center at 512 but inside the maskable safe zone; SVG untouched.
  • SITE.description (S2): trimmed from the plan's 168-char draft to 160 chars. site.webmanifest and llms.txt were then brought in line; all three carry the same string now (checked 2026-08-21).
  • ThrowCard is a plain <a>, not NuxtLink (S2): NuxtLink's own click handler SPA-navigated before a child @click.prevent could stop it (seen in the browser). The handler lets modifier / non-left clicks through and preventDefaults plain clicks, so flip / modal behavior is preserved. Server HTML is identical to what NuxtLink would emit.
  • Lint reflow (S2): eslint --fix reordered nuxt.config.ts keys and put AppLogo.vue attributes one per line; a pre-existing max-statements-per-line error in scripts/build-images.mjs was fixed. No behavior change.
  • build-og.mjs (S2): each 540² image also gets a 2 px #e5dfd4 frame to match the poster's card borders (the plan only named the rule between). JPEGs are 43 to 71 KB, under the estimate.
  • Throw meta descriptions (S2): whole sentences from mechanic while ≤155 chars; 15 throws whose first sentence runs longer are cut at a word boundary with an ellipsis.
  • error.vue (S2): uses titleTemplate itself since app.vue is not rendered on the error route; shows a small status line above the h1, one sentence, "Back to the poster".
  • Throw page extras (S2): an "All forty throws" text link top-right beside the mark (both go to /), and the content is wrapped in <main> (sitemap image discovery + plain semantics).
  • Dependency versions (S2): @nuxtjs/sitemap ^8.5.0 (plan said ^8.3.4) and @vercel/analytics ^2.0.1. Dev logs "Debug mode" for analytics; production needs Kyle's dashboard toggle.
  • Footer extraction (S2): provenance sentence byte-identical; the old lone GitHub link became "Source on GitHub" next to "Built by Monument Labs".
  • Clipart prompts (S3): the first two ("two wrestlers mid-throw", relief stele + statue group) were rejected by the OpenAI image safety filter (sexual, 2 × 400). Rephrased to "two fully robed figures in belted tunics ... judo hip throw"; both generated. Kept both PNGs and both variants.mjs entries (a/b precedent); shipped b, the statue group on a round plinth, because the relief's figures are too small inside the 5/3 tile crop.
  • Site copy (S3, task 3.6 done): the four site / OG / Organization / WebSite descriptions on monumentlabs.io now end "...We build and operate our own AI products." and the keywords meta no longer enumerates four product names.
  • Not committed (S2, S3): both repos' changes are in the working tree only, gated on Kyle's go. Kyle's long-running ML dev server on :3080 was reused for verification and left running.
  • Trailing-slash redirect: the local Nitro preview serves /throws/tai-otoshi/ as 200; the 308 to the no-slash URL comes from vercel.json trailingSlash: false. Confirmed on Vercel in Sprint 4.1.
  • Canonical host flipped to www after the first deploy (S4): the plan and the first deploy made the apex canonical with www 308-ing to it; Kyle flagged that every other Monument Labs product is www-canonical, so Vercel was re-pointed (www.gentleway.ink primary, apex 308 → www) and SITE.url, vercel.json, robots.txt, llms.txt, READMEs and STATE.md were switched to https://www.gentleway.ink; canonical, og:url, sitemap and JSON-LD follow from SITE.url. The Sprint 2 samples under samples/ (captured before the flip) still show the apex host; the samples/prod_* files are post-flip.
